## 1. First impression

### A — 生産技術（展開図を描く側）

- **五形状しかない。** `math.js` の `F` は `cylinder_shell / cone_frustum / eccentric_reducer / header_with_branch / branch_stub`。エビ管・角丸・ホッパ・三又がない。うちの今月の仕事でこの五つだけで済む月は無い。
- **板厚が入らない。** 画面に t の欄が存在しない。`math.banner`「半径は、入力値をそのまま基準面の半径として使用します。板厚、各種の代（しろ）、溶接ギャップ、カーフは考慮していません。」図面に書いてある内径・外径から展開半径を作るのは私の手計算で、その係数の規則は無い（`READINESS.md`：**minimum K-factor** に規則なし）。毎日使う道具としてここで終わる。
- **同径Tが拒否される。** `v.tangent`「｜軸オフセット｜＋枝管半径…は、母管半径…より小さくしてください。接する場合、部分的な相貫、同径の相貫は未実装です。」製缶の枝管で一番多いのが同径。一番多い仕事を拒否する道具を現場には置けない。
- **DXFに、どちらの面にけがくか・継目がどこか・巻き軸がどれか、が書かれていない**（`READINESS.md`  geometry (4)、`cn.seams.tip`「DXFファイルには、継目もロールの軸も記されていません」）。にもかわらず `mfg.foot` は「すべてのファイルは…単位、けがき面を記しています」と書く。**同じ製品の中で矛盾している。** 板を1枚無駄にするのはこの一点。
- **印刷できない。** `job.js` に印刷ボタンは無い。出力はDXFのみ。1:1タイル印刷と100 mm検尺線が無いので、手けがき班はこの出力を使えない。

### B — 購買

- **値段が無い。** `PRICING_AND_PAYMENT.md` の ¥48,000/席/年 は提案で、公表価格ではない。`COMPETITIVE_RACE.md`：「**None published**; NOT PLANNED, owner decision」。**見積書が出せない相手とは稟議を起こせない。**
- **契約書が無い。** 「All rights reserved. Evaluation use only — terms to be provided by the owner」、LICENSEファイルなし、三条の法務文書は「DRAFT — not reviewed by a lawyer」、placeholders open。情報システムと法務が最初に止める。
- **Windowsで動いたことがない。** wine 9.0のみ、未署名。うちのPCはWindows 11日本語版、一般ユーザー権限。「Windows protected your PC」が出る実行ファイルを配布する業者は、稟議の土俵に上がらない。
- **図面の保密が説明できない。** V-21 データベース非暗号化、V-22 鍵管理、V-23 MFAなし、サーバーはTLSなし（V-20）。加えて `convert.js` は `localStorage` の `nf_recent` に**アップロードしたファイル名を平文で5件保存する**（`saveRecent({ id, name: file.name, ts })`）。客先の図番・品名がブラウザに残る。削除機能も無い（ユーザーは無効化のみ、監査に氏名とアドレスが永久に残る）。
- **サポートと契約主体が空白。** 創業者はインド在住・未成年（`PRICING_AND_PAYMENT.md` §6）、JST窓口は提案段階、紹介経路は創業者がCBDOを兼務する関連会社。営業時間内に日本語で電話が取れる相手がいない。

## 2. Main task walk-through

### 2.1 PDFをドロップ → DXF（`convert.js`）

**欠けているもの（この画面で私が探すもの）：** ページ総数と複数ページ一括、図番・品名、板厚・材質、ビュー分離、寸法文字の読み取り、スキャン図面の扱い、弦公差の設定。`conv.f.tol`「曲線の弦公差（mm、任意）」と `conv.f.tol.hint`「空欄の場合は変換プログラムの既定値を使います」はカタログにあるが、この画面には欄が無い。**折れ線の粗さを決める唯一の数字が、利用者から見えない既定値になっている。**

**うちで止まる理由：** 製缶図面の入社は今もPDFスキャンが多い。`conv.rules`「スキャンまたはラスターの図面は拒否します」。ベクタPDFでも寸法は読まない。つまりこの機能は「線を引き直す前の下敷き」以上ではなく、それでいて入口では *verified flat-pattern* と名乗る。`README.md` は「no geometry kernel, PDF or OCR technology has been selected」と書き、`MASTER_GOAL.md` は図面読み取り未実装と言い、ギャップ表は DONE 3.1 と言う（`COMPETITIVE_RACE.md` L/P0-6）。**自社の資料が三通りのことを言っている状態で、客に機能説明はできない。**

### 2.2 数値入力 → 円錐・偏心大小・枝管（`math.js`）

**分かりやすい点（理由付きで評価する）：**
- 全角数字をASCIIに直す（`toAscii`、`focusout` で表示値も書き換える）。日本語IMEで寸法を入れる現場では、これは実際に事故を減らす。
- 単位違いの疑いがある値は二段階確認（`math.plaus.t`「通常と異なる寸法です。単位（mm）を確認してください。」→ `math.run.unusual`「この値のまま実行」）。500と5000の取り違えは現場で起きる。これは効く。
- `v.below` が「工学上の規則ではなく実装上の下限です」と言い切る。制限を工学のふりをさせないのは誠実。
- `job.clone`「この値で新規計算」。似た部材を繰り返す製缶では、これが正しい操作。

**混乱する点：**
1. **基準面の選択肢に文字が出ない。** `math.js` は `SURFACES.map((o) => [o, t(\`sref.${o}\`)])` でラベルを作るが、`MSG` に `sref.unknown / sref.outside / sref.inside / sref.neutral` は**存在しない**（`sref` は `ID` 表にあり、`t()` は `ID` を見ない）。したがってプルダウンは `sref.unknown` `sref.outside` `sref.inside` `sref.neutral` と表示される。**内寸／外寸／中立面を選ぶ、この製品で最も安全上重要な操作が、英語でも日本語でも識別子で表示される。** `v.joint.pair` も同じ関数を使うので、拒否メッセージは「現在は、母管：sref.outside、枝管：sref.unknownです。」と読める。他方 `job.js` は `named('sref', v)` で `ID` を引くため、結果画面では「外面」と正しく出る。**入力画面と結果画面で同じ概念の表記が違う。**
2. **タブの名前が出ない。** `job.js`：`TAB_KEY = { result: 'math.result.h', pattern: 'stage.aria', details: 'pane.props.h' }`。`stage.aria` と `pane.props.h` は EN/JA どちらのカタログにも無い。**展開図タブと詳細タブが `stage.aria` / `pane.props.h` という生のキーで表示される。** 結果タブは `math.result.h`＝「得られる結果」で、これは入力画面の未来形の文言。終わったジョブに「得られる結果」は日本語として変。
3. **「このビルドの範囲」パネルが全部キーになる。** `lis('math.result', 5)` / `lis('math.conv', 4)` / `lis('math.planned', 6)` は `math.result.1`…`math.result.5`、`math.conv.1`…`.4`、`math.planned.1`…`.6` を引くが、カタログにあるのは `.h` `.lead` `.tag` だけ。**板厚・カーフ・継目・けがき面を説明する、誠実さの核心である15項目が、両言語でキー文字列として並ぶ。** 読めない注意書きは、無いのと同じ。
4. **初期値が入っている。** `F.cylinder_shell` は r_dev 500 / length 1000。コメントは「no engineering value is guessed: an empty or unreadable field is an error, never a default」と書くが、実際は例示値が埋まっており、`math.tag.example`「入力例」の小さな札だけが頼り。**開いて押すと、それらしい円筒のDXFが出る。** 例示は「空欄＋プレースホルダ」にすべき。
5. **基準面が1宣言で2半径を兼ねる。** `sref(part)` の1値で、取合い半径と展開半径の両方を検査する（`ref === 'neutral' && !same` はエラー）。実際の仕事は「取合いは外面、展開は中立面」です。**その組み合わせを宣言できない。** 中立面を選ぶと両半径が一致しなければならず、板厚のある部材では中立面宣言が実質使えない。`SENT` には「半径は、入力値をそのまま基準面の半径として使用します」と「半径は、入力値をそのまま基準面（**中立面**）の半径として扱います」の二文が併存し、後者は宣言が unknown/outside/inside の場合と矛盾する。
6. **セットインが無い。** `joint` は `''`（未宣言）と `set_on` のみ。穴に差し込むセットイン、部分溶込、開先付きの枝管が表現できない。`set_on` を選ぶと母管外面・枝管内面が必須（`v.joint.pair`）だが、板厚が無いので**内径＝外径−2t も 中立半径＝内径+k·t も、私が電卓で出すことになる。** K の規則は無い（`READINESS.md`）。ここが毎日の作業の bottleneck。
7. **符号・投影の取り決めパネルが枝管系にしか出ない。** `convSec.hidden = !/branch/.test(fam)`。円錐・偏心大小にも継目 theta=0 とけがき面があるのに、その利用者は取り決めを読まない。
8. `sk.notdrawn`「図示していないもの：母管の展開半径 150 mm → 展開幅 2π·r = 942.478 mm」。**計算値を出しながら「図示していないもの」と言う。** 日本語として意味が通らない。「展開幅（参考）」でよい。

**結果画面（`job.js`）で止まる点：**
- **状態の表示が実体を隠す。** `state = c.superseded_by ? 'SUPERSEDED' : !c.patterns.length ? 'NO_RESULT' : c.state`。展開図が無いジョブは全部「結果なし」に丸められる。入力拒否（`REFUSED`）と、計算したが検証で落ちた、は現場では全く別の話です。
- **閾値を英文から正規表現で拾っている。** `const thr = /s_end\s*>\s*([0-9][0-9.eE+-]*)/.exec(c.outcome)`。 engineering の境界値をクライアントが散文から切り出している。エンジンが `s_end_min` を数値で返すべき。英文の語順が変わった瞬間に消える表示で、しかも消えたことに誰も気づかない。
- **未確定でもDXFが出る。** `blocked()` は `REVIEW_REQUIRED` と `APPROVED` 以外を止めるだけ。`READINESS.md` の2件の INCONCLUSIVE は「both end REVIEW_REQUIRED with a DXF offered」。**判定できていない部材のファイルが、確認待ちの札付きで手元に落ちる。** 現場では「ファイルが来た＝使ってよい」と読む。出すなら、ファイル名とDXF内文字に「未確定」を入れること。
- **数値の読みやすさ。** 検証グリッドは `num(k.difference)` を単位なしで出し、`n3` は 1e-3 未満を指数表記にする。差が `2.00e-4` と出ても、現場は「0.0002 mm、許容0.01 mm」と読みたい。単位は `c.foot` の注記にしか無い。
- **証拠が生JSON。** `recordsHtml` は `JSON.stringify(r.payload, null, 1)` を `lang="en"` でそのまま出す。うちの技術者に「これを読んで判断してくれ」とは言えない。
- **訂正が組立限定。** SERVER「依存関係の伝播を伴う訂正は、組立のジョブでのみ実装されています」。**単独の円錐で「内径だった」を訂正しても、影響は伝播しない。** 現場で最も多い訂正が対象外。
- **免除の権限が広い。** `canEdit = () => role() !== 'viewer'`、`scrutinyHtml` の免除ボタンは `canEdit()` で出す。**管理者（情報システム担当）が、技術者の確認事項を理由5文字で「免除」できる。** `s.e.obl` は5文字下限。安全に関わる判断の権限分離が無い。
- **図番が無い。** 入力は `project` と数値だけ。`req.hint`「元図面とは連携していません」。図番・品名・材質・板厚・枚数の欄がどこにも無い。**うちは図番で仕事を追う。** 「ジョブ #123」では伝票にも現物にも結び付かない。
- **Changesタブの外形寸法はブラウザ計算。** `extent(p)` が頂点から x/y 範囲を出す。見積りに使う数字が、閉包ハッシュの外で作られている。

### 3.2 法的・信頼上、危険な語

- **「認証された上界」**（`q.hint`「eps_rep は偏心レデューサを除き、認証された上界です」）。日本語の「認証」は第三者認証機関を連想させる。区间演算で証明したという事実と、第三者が認めたという誤解は別。**「区間演算で上界を証明（第三者認証ではない）」** に直す。さらに `READINESS.md` は「`eps_num` and `eps_rep` are not proven upper bounds (G08 INCONCLUSIVE on every job)」と言う。**画面の断定は登記簿と矛盾している。今すぐ落とすべき一文。**
- **「暗号化して保存します」**（`doc.accepted`、`docs.none.p`）。blobの暗号化は事実だが、鍵はデータ隣接（V-22）、DBは非暗号化（V-21）。この一文だけで客は「図面は安全」と読む。**「ファイル本体は暗号化して保存しますが、データベースは暗号化されていません。鍵は同じPC内にあります」** を併記しない限り、この文言は使ってはいけない。

## 4. 信頼 — 何が信じさせ、何が疑わせる

### 信じさせる側（理由付き）

1. **検算が、作った式と別の式で、数値で見える。** `checksHtml` が `c.primary`「計算値」／`c.reference`「参照値」／`c.difference`「差」／`c.tolerance`「許容差」を並べ、`c.method` に独立性クラス（I-F）を出す。**差と許容差を隠さない道具は、この市場に無い**（`COMPETITIVE_RACE.md`：どの業者も誤差限界を公表していない）。これは本物。
2. **拒否が具体的。** `branch_angle_not_verifiable`、`v.tangent`、`s_end > {n}`。「分からない」と言える道具は、黙ってそれらしい線を出す道具より安全。
3. **旧版のファイルが出ない。** `mfg.note`「却下されたジョブと旧版のジョブのファイルは、サーバーが提供しません」。訂正後に古い展開図が現場に残る事故は実際に起きる。これを止める設計は正しい。
4. **けがき面の警告が具体的。** `SENT`「反対の面にけがくと、部材は鏡像になります（偏心した斜めの枝管では、数十ミリメートルの食い違いになります）」。**この一文は、うちの板を1枚救う種類の一文。**
5. **再計算照合とハッシュ。** `r.replay.hint`、`job.replay.tip`「別プロセスで再計算し、閉包ハッシュを比較」。

### 疑わせる側（重い順）

1. **鏡像・回転を検出できないと自認している。** `READINESS.md`：「the cylinder and eccentric-reducer verifiers do not catch a rotated or mirrored part (review C RC-09, RC-10)」。**現場で最も高くつく失敗が、五形状のうち二形状で素通りする。** 検算を売りにする道具が、最大の事故様式を見逃すと自分で書いている。
2. **絶対に落ちない検査がある。** 「the opening-area check computes on absolute coordinates and has a tolerance that can never fail」。**落ちない検査の PASS は、無いより悪い。** 「開口の面積＝表面積」に合格印が付くのを見て、私は他の合格印も疑う。
3. **誤差限界が証明されていないのに、画面は証明済みと言う**（§3.2）。G08 は全ジョブで INCONCLUSIVE。
4. **検算の判定基準が、エンジンの実装限界を写している**（RC-28）。「独立」は式の独立性であって、限界の独立性ではない。ここは正直に書かれているが、独立性の主張の強さは落とすべき。
5. **製作技術者のレビューが0/56。** 全アルゴリズムが EV-1。**うちは「誰がこれで板を切ってよいと言ったか」で動く。** その名前が無い。K の最小値、継目の最小隙間という、私が毎日使う二つの規則が存在しない。
6. **DXFを読み返しているのが自前のリーダーだけ。** CAM受入未試験、JWWなし、Shift_JISなし。うちのレーザーは層名と単位と文字コードで動く。**「開けた」は「切れた」ではない。**
7. **未確定・不合格でもファイルが出る**（§2.2）。
8. **図面と展開図が結び付かない**（`req.hint`）。追跡可能性を売るなら、図番が記録に無いと話にならない。
9. **ハッシュが署名も外部固定もされていない**（V-25/V-28）。監査の主張は「同一PC内の整合性」までで、うちが客先に提出する証拠としては弱い。
10. **EV-1 という札が画面に出るが、意味の説明が無い。** 現場の技術者は EV-1 を読めない。平易な日本語で「独立レビュー未了」の意味を書くべき。
