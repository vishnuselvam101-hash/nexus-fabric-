# Engineering Benchmark Plan

Version 0.1 · 18 November 2026 · Becomes binding as Specification 10

**No benchmark data exists yet.** Nothing in this plan assumes its availability; data needs are listed in §9. Only drawings with written authorisation from their owner are admitted.

## 1. Purpose

Provide the evidence on which engineering reliability claims, technology selections and release decisions rest. A capability is not considered reliable because it passes tests; it is considered *evidenced to a stated level* on a *stated corpus*, and reports must say both.

## 2. Corpus structure

| Tier | Content | Source | Role |
|---|---|---|---|
| **S — Synthetic analytic** | Parametric parts with closed-form developments and intersections; drawings rendered from known models (vector, then degraded to simulated scans) | Generated by us | Exact ground truth; regression floor; can start immediately. Not a substitute for real drawings |
| **H — Historical factory** | Completed jobs: drawing, approved development/DXF, decisions | Factory (authorised) | Realistic inputs; ground truth = engineer-approved output (which may itself contain error — see §4) |
| **P — Physical trial** | Selected jobs cut, formed, assembled and measured | Factory + us | The only tier that evidences physical conformity |
| **A — Adversarial** | Ambiguous, contradictory, incomplete, out-of-scope, malformed and hostile files | Both | Tests correct *refusal* |

Each tier is split into **development** and **held-out** sets. Held-out jobs are not viewed by developers and are used only for periodic reporting.

### Coverage matrix (each cell needs jobs in every available tier)

| Dimension | Categories |
|---|---|
| Input type | Vector PDF · scanned PDF · photo/image · DXF · DWG · multi-page · multi-view |
| Scan condition | Resolution bands · skew · perspective · noise/fax artefacts · stamps/handwriting · folded/creased |
| Language | Japanese · English · mixed |
| Geometry | Cylinder · concentric reducer · eccentric reducer · oblique cone · tee branch · oblique branch · multi-branch · rectangular-to-round · multi-segment (lobster-back) bends · planar plates · custom |
| Material / thickness | Per factory range (FR) |
| Completeness | Fully dimensioned · redundant · under-dimensioned · contradictory |

Minimum counts per cell are set in Specification 10 from statistical requirements; no numbers are asserted here.

## 3. Job record

Original file(s) and hash · authorisation reference · input-type and condition labels · ground-truth observations (dimension values, units, tolerances, the entity each refers to, view classification) annotated by two people independently with adjudication · reference 3D geometry where available · approved development and DXF · fabrication decisions (division, seams, allowances) and process data · inspection measurements where available · engineer's time spent originally (if recorded) · review notes · expected system outcome (*process / review-required / reject*).

## 4. Ground truth quality

- Annotation agreement between annotators is measured and reported; low agreement marks a job as ambiguous rather than forcing a label.
- Historical approved outputs are treated as reference, not truth. Disagreements between system and reference are adjudicated by a factory engineer and classified: system error · reference error · both acceptable · ambiguous drawing.
- Tier S truth is exact by construction and is used to validate the metrics code itself.

## 5. Metrics

| Area | Metrics |
|---|---|
| **Dimension extraction** | Precision and recall of detected dimensions; value accuracy (exact-match rate of numeric value, unit, tolerance); character error rate for JA/EN text; **dimension-to-entity association accuracy**; view classification accuracy; provenance-class correctness; **false-accept rate** (wrong observation presented without a flag) reported separately from flagged errors |
| **Geometric reconstruction** | Parameter error versus reference; constraint residuals; correct detection of under- and over-determination; maximum and RMS surface deviation, boundary deviation; correct enumeration of alternative interpretations |
| **Flat-pattern accuracy** | Boundary deviation from reference pattern (max, RMS, after best-fit alignment and without); edge and seam length agreement; area agreement; fold-back deviation onto target surface; seam closure gap; correct development class label; for approximate developments, stated versus measured distortion |
| **Uncertainty** | Calibration: how often the reference falls within stated intervals at each stated coverage level; interval width (sharpness); fraction of jobs sent to review because of uncertainty; cases where stated uncertainty was exceeded |
| **DXF validity** | Independent-parser load success; closed-profile, self-intersection, duplicate, zero-length and overlap counts; units/scale/extents correctness; layer conformance; re-import geometry deviation from approved geometry |
| **CAM compatibility** | Load without modification in each target CAM/nesting system; warnings; manual fixes needed; toolpath generation success (requires system access — FR) |
| **Processing time** | Per stage and end-to-end; median, p95, maximum; peak memory; timeouts; hardware profile and concurrency recorded (methodology: Spec 01 §7.1) |
| **Human correction time** | Engineer time from upload to approvable job; number and type of corrections; compared with baseline manual time on the same job (shadow pilot) |
| **Physical inspection** | Measured dimensions versus drawing with measurement uncertainty; fit-up gaps at seams; conformity decision per drawing tolerance; rework required; attribution of deviation (pattern · process parameter · execution · measurement) |
| **Safety (refusal)** | On tier A: correct review/reject rate; **false-release rate** (a job that should have been stopped reaching "passes all automated gates"); hostile-file handling without compromise or crash |
| **Reliability** | Run-to-run and cross-platform reproducibility; regeneration of archived results |

The headline safety metrics are **false-accept rate** (extraction) and **false-release rate** (end-to-end). Averages must not hide them; they are reported with counts and confidence intervals, and every instance is individually analysed.

## 6. Protocols

- **Automated harness** — runs the corpus per commit/night; stores results with commit, algorithm versions, dependency versions and hardware fingerprint; diffed against baselines.
- **Stage-wise and end-to-end** — each stage is scored both on ground-truth inputs (isolating the stage) and on real upstream outputs (measuring error compounding).
- **Technology evaluations** — kernel, 2D library, PDF and OCR candidates are compared on the same corpus subsets (Spec 01 §4.3).
- **Competitor evaluation** — the same authorised jobs run through competitor products where their terms and the drawing owner's authorisation permit uploading; otherwise synthetic tier only.
- **Shadow pilot** — factory engineers work as usual; the system processes the same jobs independently; outputs compared before anything from the system reaches production. Time, corrections and disagreements recorded.
- **Physical trials** — pre-registered plan per trial: part, tolerance, process parameters, measurement method and instrument uncertainty, acceptance rule fixed *before* cutting. Results feed process calibration data with evidence links.

## 7. Governance

- Authorisation register: owner, scope of permitted use (internal testing / external reading services / competitor tools), expiry.
- Benchmark data stored under the same security controls as customer data; not used for model training unless the authorisation says so; never committed to this repository.
- Corpus is versioned; results always cite the corpus version.
- Held-out access is restricted and logged.
- Failures found in the field or pilots are added to the corpus as regression jobs.

## 8. Acceptance criteria

Thresholds are **not set in this plan**. They will be defined in Specification 10 from: customer tolerances (FR), verification policy (Spec 05), and the first measured baselines. The structural criteria fixed now:

1. No release-capable shape module without tier S and tier H coverage, and tier P evidence for its process models.
2. Any false release on the held-out or adversarial set blocks the affected capability until root cause is resolved and a regression job exists.
3. Reported results always state corpus version, tier, sample size and confidence interval.
